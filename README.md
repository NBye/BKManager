# ES Bookmark Manager Chrome Extension

离线优先的 Elasticsearch 浏览器收藏插件。

项目 Logo：`public/logo.svg`。

## 安装到 Chrome

1. 打开 `chrome://extensions/`。
2. 开启右上角“开发者模式”。
3. 点击“加载已解压的扩展程序”。
4. 选择项目下的 `dist` 目录。
5. 打开插件设置，填写 ES 地址、授权 Key 和索引前缀；也可以在收藏夹首页选择“离线使用”，暂时不配置 ES。

Chrome 会记住这个 `dist` 目录。以后更新插件时，只要目录位置不变，就不需要重新选择文件夹。

## 配置 Elasticsearch

实际索引名为：

```text
索引前缀 + bookmarks
```

例如 `bm_company_` 对应 `bm_company_bookmarks`。

推荐使用 HTTPS。保存 ES 地址后，插件只会申请对应主机的主机权限。`localhost` 允许使用 HTTP 便于本地调试。

授权 Key 不需要集群级别的 `monitor` 权限。已存在的索引至少需要目标索引的读取和写入权限；如果希望插件自动创建索引，还需要 `create_index` 权限。

配置页面支持“表单模式”和“JSON 模式”，两边内容会自动联动。保存前可以先用“测试连接”确认地址和 Key 可用。

## 更新插件

推荐流程：

```bash
git pull
npm install
npm run build
```

然后进入 `chrome://extensions/`，点击本插件的“重新加载”。

如果插件就是从 `dist` 目录加载的，更新后继续使用同一目录即可，不需要重新选择扩展文件夹。Chrome 对未打包扩展不会保证文件变化后立即热刷新，所以更新后建议手动点一次“重新加载”。

如果仓库已经发布了 `dist/` 编译产物，`git pull` 拉到新的 `dist` 后可以直接在 Chrome 中重新加载；如果仓库没有包含 `dist`，就使用上面的 `npm run build` 重新生成。

## 离线与同步

- 未配置 Elasticsearch 时，可以直接进入离线模式，新增、修改、删除和拖拽都保存在本地。
- 已配置但暂时无网络或 ES 不可用时，本地操作仍会先保存，联网后由插件继续同步。
- 离线模式创建的数据，首次绑定 Elasticsearch 后会自动迁移并上传。
- 绑定 ES 后，插件以 ES 中的有效数据为准刷新本地缓存。
- 收藏夹弹窗和管理页会自动触发同步，通常不需要手动刷新。
- 收藏管理页右上角仍有“同步”按钮，可以用于主动全量校准。

## 日常使用

- 点击插件图标打开收藏夹，可在树状布局和宫格布局之间切换。
- 树状和宫格布局都支持拖拽移动、排序和进入文件夹。
- 页面右键可以收藏当前网页。
- 链接右键可以收藏链接地址。
- 选中文案后右键可以将文案收藏到根目录。
- 文案节点在宫格模式下显示为四个字符的图标，左键点击即可复制内容。
- 管理页支持目录和收藏的编辑、级联删除、导入备份和导出全部。

## 备份与恢复

导出的备份是 JSON 文件，包含本地当前的全部有效节点。

导入备份时会先校验节点结构、父级关系和链接地址。你可以选择“全量覆盖”，也可以进入合并模式处理 URL 冲突。绑定 ES 时，恢复完成后会继续同步到 Elasticsearch。

建议在以下场景导出备份：

- 准备修改 Elasticsearch 配置或索引前缀。
- 准备把数据迁移到新的工作区。
- 大批量整理收藏前。

## 常见问题

**插件更新后没有变化？**  
进入 `chrome://extensions/`，点击插件卡片上的“重新加载”按钮。未打包扩展不会总是自动感知文件变化。

**同步失败但离线可以继续用吗？**  
可以。本地操作会先保存到 IndexedDB，网络或 ES 恢复后再继续同步。

**删除后 ES 里还会看到旧数据吗？**  
普通删除会同步删除本地和 ES 中对应节点。若索引刷新延迟，稍后刷新页面即可看到最终状态。

**修改 ES 配置会丢数据吗？**  
不同索引前缀对应不同工作区。切换前建议先导出备份，确认需要迁移的数据再操作。

**哪里可以看完整使用说明？**  
打开收藏管理页左侧导航的“使用说明”，页面内容会渲染当前 `README.md`。
